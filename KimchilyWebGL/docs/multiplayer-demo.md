# 함께 만드는 작은 월드 — 시연 시나리오

목표는 3명이 휴대폰으로 같은 월드에 들어가 대화하고, 제작자가 TypeScript 규칙을 바꾸어
다른 협동 게임을 발행하는 모습을 3~5분 안에 보여 주는 것입니다.

## 1. 만나서 인사하기 — 현재 구현

각자 홈/QR 화면에서 닉네임을 정하고 같은 게시 월드에 들어갑니다. 자동으로 같은 방에
연결되고 Unity 내부 **채팅**을 펼치면 대화할 수 있습니다. 메시지는 TMP 채팅창과 발신
캐릭터 위 말풍선에 표시됩니다. 늦게 입장한 사람도 최근 대화와 현재 위치를 받습니다.
별도 웹 로비 화면은 매칭 전에 인사하는 UI로 유지합니다. 현재 매칭은 방 코드 공유 방식입니다.

## 2. 서로 찾아가기 — 현재 구현

자기 캐릭터와 다른 참가자의 캐릭터·닉네임이 보입니다. 걷거나 달리고 점프하며 같은 곳에 모입니다.
서버는 위치·방향·애니메이션 상태의 유효성을 확인하고 방 안에 전달하며, 클라이언트는
원격 이동을 부드럽게 보간합니다. 다른 월드·버전·방에는 플레이어가 나타나지 않아야 합니다.
현재는 클라이언트 이동의 검증·중계 방식이며 서버 물리나 손 흔들기 이모트는 구현하지 않았습니다.

## 3. 세 발판과 하나의 문 — 예정

문 앞의 세 발판을 3명이 나누어 밟으면 카운트다운이 시작됩니다. 3초 동안 유지하면 문이 열리고,
한 명이 내려가면 카운트다운이 멈춥니다. 채팅으로 역할을 정해 협동을 유도합니다.
서버가 발판 점유·타이머·승패를 판정하고 모든 참가자에게 같은 라운드 상태를 전송합니다.
중간 입장자는 현재 점유와 남은 시간을 받아 곧바로 상황을 이해합니다.

## 4. 제작자가 규칙 바꾸기 — 예정

제작자가 `.ts`에서 발판 개수, 유지 시간, 색상·이펙트·안내 문구를 바꾸고 새 버전으로 발행합니다.
기존 방은 기존 버전을 계속 사용하고 새 방은 새 규칙을 사용합니다. 서버가 검증 가능한
선언형 규칙을 먼저 지원하고, 임의 TypeScript의 서버 실행은 별도 격리 설계 후 검토합니다.
클라이언트의 성공 메시지만으로 보상·점수를 확정하지 않습니다.

필요한 SDK 설계 후보는 방 참가자 조회, 방 이벤트 구독, 플레이어 상호작용 요청,
서버에서 확정된 게임 상태 구독입니다. **이 API와 미니게임은 아직 구현되지 않았습니다.**
현재 TypeScript 제작·실행 기능과 이번 채팅 연결을 토대로 단계적으로 확장합니다.
