# 스킬 커맨드 입력 (2026-10-22)

## 조작과 설정

| 동작 | 기본 커맨드 |
|---|---|
| 폭주 | 앞 → 앞 → Space |
| 프렌지 ON/OFF | 아래 → 아래 → Space |
| 커맨드 설정 | F6 (마을 또는 레이드) |

앞/뒤는 해당 커맨드의 첫 입력 당시 캐릭터가 바라보는 방향이다. 왼쪽을 보고 있으면 폭주는 왼쪽, 왼쪽, Space다. 같은 방향은 키를 떼었다가 다시 눌러야 한다. 키 사이 간격은 최대 0.45초, 한 커맨드는 최대 1.4초이다. 기존 앞앞 달리기와 스킬 슬롯 단축키는 유지한다.

F6에서 스킬을 선택한 뒤 앞/뒤/위/아래/Z/X/Space 버튼을 순서대로 눌러 조합을 구성하고 저장한다. 조합 길이는 2~8개이며 마지막 키는 Z, X, Space 중 하나다. 다른 스킬과 같은 조합 또는 먼저 실행되어 뒤쪽 조합을 방해하는 접두 조합은 저장을 거부한다. 여러 조합이 마지막 부분에서 동시에 맞으면 가장 긴 조합을 우선한다. 커맨드 해제 및 기본값 복원을 제공한다.

설정은 이 PC의 Unity PlayerPrefs `dawn_skill_commands_v1`에 버전 1 JSON으로 저장된다. SQL/계정 간 동기화는 이번 범위에 포함되지 않는다. 읽을 수 없거나 유효하지 않은 설정은 기본값으로 복구한다.

## 입력 처리와 권위

`Client/SkillCommands.cs`는 Unity와 분리된 순수 입력 인식기다. 매 프레임 눌린 키 상태의 상승 에지만 받아 반복 키가 눌린 상태를 두 번 입력으로 세지 않는다. 조합이 완성되면 스킬 ID와 소비한 마지막 키를 반환한다.

`RaidDemoApp.Commands.cs`는 결과를 기존 `pressedSkills` 및 `PlayerCommand.Bit` 경로에 넣는다. 서버 프로토콜이나 피해·버프 값을 직접 변경하지 않는다. 방장 계산과 서버의 C# 판정 검증을 그대로 통과한다. 소비한 X/Z/Space는 키를 뗄 때까지 일반 공격·슬롯·대시로 중복 실행되지 않는다. 커맨드 중간 키의 원래 동작(방향 이동, 달리기 등)은 유지한다.

채팅, IME 조합, 텍스트 입력창, 메뉴, 인벤토리, 스킬창, 설정창, 보상창, 조우 연출, 포커스 상실 시 입력 버퍼를 비운다. 전투/마을 전환 및 방 이동 시에도 버퍼를 초기화한다. 막힌 상태에서 누르고 있던 키는 창을 닫아도 새로운 입력으로 처리하지 않는다.

프렌지 ON/OFF 판정과 기본/2도류 모션 전환은 전투 코어가 담당한다. 설정창 하단에 서버에서 받은 현재 프렌지 상태를 표시한다.

## 검증

`dotnet run --project CommandTests/CommandTests.csproj -p:NuGetAudit=false`

순수 인식기 30개 검사 통과: 양방향 facing, 첫 입력의 facing 고정, 반복 방향의 release 요구, 키 유지 중 재발동 방지, 입력 간격/전체 기한, 채팅/포커스 초기화, Z/X 커스텀, 최장 일치 우선, 반대 방향 동시 입력, 시계 역행, 잘못된 설정과 조합 충돌.

`--commands-review --output <절대경로>`는 오프라인 시각 검증을 실행한다. F6 설정 화면, 프렌지 OFF/ON 대기·평타, 폭주 발동을 캡처하고 `commands-review.json`에 결과를 남긴다. 동일한 인식기에 결정적 입력 샘플을 주입하여 일반 스킬 요청 경로로 실행하며, 물리 키보드 조작이나 서버 4인 검증을 대신하지 않는다. 실제 실행 결과는 산출물 JSON을 확인해야 한다.
