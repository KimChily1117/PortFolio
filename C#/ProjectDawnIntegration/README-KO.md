## 작업 위치와 원본

- 개발 루트: `E:\task\ProjectDawnIntegration`
- 서버 작업 사본: `Server` — `E:\task\Server\Server`에서 소스 복사, bin/obj/.vs/.git 제외.
- Unity 공통 패키지: `Packages/com.projectdawn.combat` — 엔진 참조 없는 순수 C#.
- 서버용 같은 소스 빌드: `Build/CombatCore/ProjectDawn.Combat.csproj` — .NET Standard 2.1.
- Unity 검증 프로젝트: `UnityValidation` — Unity 2022.3.16f1. 기존 게임 씬을 복사한 완성 클라이언트가 아니다.
- 원래 Dawn 클라이언트·서버, 데모 클라이언트·빌드·게임 리소스는 수정하지 않았다. 통합 검증에서는 작업 사본의 실제 서버 세션/매칭 코드를 루프백 소켓으로 실행했다. 운영 서버 배포/공유기 설정/Git push는 수행하지 않았다. 코디 영속화를 위해 개발 DB에 nullable Appearance 열을 추가했다. 새 흐름 검증용 계정 네 개와 해당 캐릭터 장비는 기존 SQL DB에 저장했다.

서버 원본 폴더에 `.git` 디렉터리가 있지만 Git은 작업 트리로 인식하지 않았다. 이를 복구/덮어쓰기하지 않고 별도 작업 사본으로 시작했다. 원본 Unity 버전은 Dawn 2021.3.11f1, 데모 2022.3.16f1이며 설치된 2022.3.16f1에서 패키지를 검증했다. Dawn 전체 프로젝트의 버전 이전은 아직 수행하지 않았다.

서버가 승인된 공격을 자체 판정하므로 명중 보고 누락만으로 피격을 없앨 수 없다. 플레이어 공격은 원래 입력과 일치하는 방장 제안이 있어야 평가된다. 늦은 점프가 피해를 취소하면 같은 미확정 구간의 넉백·경직·후속 공격도 다시 계산한다. 확정 사건은 경계를 넘을 때만 생성되고 재계산 중 Lua·사운드·DB를 호출하지 않는다.

새 네트워크 경로는 `GameRoom_Raid.cs`, `ClientSession_Raid.cs`, `Protocol/Raid.proto`, `Client/RaidNetworkClient.cs`에 있다. 버전 협상 → 기존 4인 매칭 → 4인 입장 완료 → 입력 수신/방장 제안 → 서버 확정 스냅샷/사건 전송까지 연결했다. 기존 AI와 피격/이동 처리의 우회도 차단한다. 방장 이탈/로딩 취소 시 기존 씬 이동 절차로 마을에 복귀한다.

검증 사례에는 다음을 포함한다.

- 늦은 점프 → 피해·넉백 취소 → 후속 공격 회복. 제때 도착한 입력과 최종 상태 일치.
- 입력/제안 마감 직전·정확히 마감·직후, 수신 후 방 큐에서 지연된 입력.
- 확정 HP 불변, 스냅샷 변경이 내부 상태에 영향을 주지 않음.
- 다른 참가자/전투/연결 세대/호스트 위조, 미래 시각/시계 버전 불일치, 같은 키의 내용 변조.
- 4인의 다단히트 12회 정상 반영, 반복 재판정 후 피해·사건 중복 없음.
- 명중 연출 확정/빗나감/만료/재접속 처리와 다중 대상·다단히트 구분.
- 20개 입력 도착 순서 섞기와 중복 전송 후 정순 입력과 최종 상태·사건열 일치.
- 큐 용량/재판정 예산 초과 및 시계 역행 시 검증을 건너뛰지 않고 중단.

전체 로그 (`Logs/validation-all.log`, 로컬 검증 자료), 네트워크 로그 (`Logs/network-validation.log`, 로컬 검증 자료), Unity 로그 (`Logs/unity-core-validation.log`, 로컬 검증 자료)

재현: 개발 루트에서 `./Validate.ps1`을 실행하면 두 .NET 런타임 검증, 서버 빌드, 4인 네트워크 검사와 기존 서버 회귀 검사를 수행한다. `./Validate.ps1 -Unity`는 Unity 검증도 수행한다. Unity 테스트 파일은 `Tests/Program.cs`에서 생성하므로 별도 로직을 유지하지 않는다.

## V1 단계의 범위 기록 (최신 상태는 위 Unity 통합 문서 참조)

**전체 통합 완료나 4인 네트워크 빌드 완료로 보고하지 않는다.**

- 현재 전투 모델은 경계/재판정을 검증하기 위한 최소 모델이다. 정수 지면 X축·점프 높이와 제한된 공격 정의를 사용한다. 기존 데모의 2.5D 영역·21종 스킬·모션·리소스가 이식된 것은 아니다.
- `SessionBinding`은 서버가 인증/시계 동기화 후 발급하는 계약이다. 실제 서버 세션과의 연결은 구현했다. 네트워크 바인딩은 아직 시계를 신뢰하지 않으며 서버 수신 시각으로 평가한다. 시간 동기화 패킷/오차 추정과 실제 늦은 점프 보정 연결은 다음 작업이다.
- 새 버전 협상을 한 4인 파티는 실제 GameRoom/패킷 경로에서 코어를 사용한다. 기존 Unity 클라이언트는 새 메시지를 아직 사용하지 않으므로 현재 게임 실행 파일의 전투가 자동 전환되지는 않는다. 자동 클라이언트와 재사용 가능한 C# 처리기를 먼저 연결했다.
- Lua 실행기·보스 필수 패턴/추첨 검증·시전 대상 규칙은 미구현이다. 검증용 네트워크 규칙에는 단타/3단 공격만 등록했고 임의 보스 패턴 제안은 허용하지 않는다. 보스 패턴 조작 방지 전체가 완성된 것으로 설명하지 않는다.
- 예측 원장은 연출 토큰 결정만 반환한다. 기존 Unity 음향·히트스톱·이펙트에 연결하는 작업은 남아 있다.
- 확정 스냅샷 전송과 방장 이탈/로딩 취소 후 마을 복귀는 실제 소켓으로 검증했다. 비방장 이탈 시 캐릭터 유지까지 구현했다. 3분 재접속·만료 제거·자발적 퇴장·영속 보상은 후속이며 기존 합의는 유지한다. 검증 클리어는 보상을 지급하지 않는다.
- 입력/결과 캐시는 첫 버전에서 상한 도달 시 중단한다. 장시간 레이드에 필요한 정리/보존 전략과 할당 비용 최적화는 필요하다. 검증판은 방장 제안 누락이 누적 3회면 중단한다. 실측 지연을 반영한 정책 조정은 필요하다.
- 코어 단위 테스트의 L=40ms/P=20ms/W=70ms/10ms 틱은 경계 검증용 합성 값이다. 네트워크 검증판은 L=120ms/P=120ms/W=260ms/20ms 틱을 사용한다. 모두 실제 게임 지연/서버 비용 측정을 마친 제품 기본 설정이 아니다.

## V1에서 정했던 개발 순서 (1·2의 Unity 연결 부분은 이번에 완료)
