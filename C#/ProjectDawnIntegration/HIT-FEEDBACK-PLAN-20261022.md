# 본인 타격감 개선 설계 · 2026-10-22

상태: **1차 구현 완료, 영상 피드백 후 리소스 추가 반영**. 평타/프렌지·블러드 소드·오버킬의 개인 피드백 및 원본 명중 FX·데미지 숫자를 연결했다. AWS는 사용자 정지 상태를 유지한다. 아래 초기 조사 내용은 변경 전 기준이며, 최종 결과는 [구현 기록](HIT-FEEDBACK-IMPLEMENTATION-20261022.md)을 따른다.

## 목표

사용자의 우선순위는 단순히 빨리 반응하는 화면보다 **내 공격이 적에게 꽂히고, 무게가 실리고, 마무리가 터지는 감각**이다. 입력을 늦추는 것으로 무게감을 만들지 않는다. 준비 → 접촉 → 짧은 정지 → 후속 동작의 시각·소리 리듬을 맞춘다.

본인 명중의 예측 연출은 유지하되 개인 연출의 완성도를 우선한다. 실제 피해·경직·이동·점프·보스 패턴·보상은 기존 방장 계산/서버 C# 검증·확정 구조를 유지한다. 공유 연출은 기존 확정 기준을 유지하고 컷신은 계속 본인에게만 표시한다.

## 코드에서 확인한 문제와 미검증 가설

| 항목 | 확인 근거 | 개선 방향 |
|---|---|---|
| 본인 명중은 모두45ms 포즈 보관 | `RaidDemoApp.Dawn.cs: AcceptFeedback`, `.045f` | 약타/강타/다단/마무리 별 프로필 |
| 정지가 연출 전체에 묶이지 않음 | `RaidDemoApp.cs: DrawPlayer`에서 포즈 복사 후에도 displayPositions/displayHeights·PresentationExtrapolation 사용 | 몸·무기·접촉 FX의 로컬 재생 시계 정렬. 이동/점프 판정과 보스 경고 시계는 지속 |
| 실제 공격자와 다른 무기 타격음 | `RaidDemoApp.Sound.cs: PlayOriginal`, Damage에서 `sim.Players[0]` 참조 | `SourceId`의 실제 공격자·무기 참조. 2~4번 참가자의 다른 무기로 검증 |
| 파티 타격음이 본인 소리를 밀어낼 수 있음 | 같은 함수의 전역 lastHitSound,60ms 제한 | 본인 우선 재생, 공격자별 제한·총 동시 발음 상한·중복 키 유지 |
| 진동의 공격별 차이가 작음 | 피해300 기준2/5, 강한 스킬 시전은 공통6 | 피해 숫자 대신 스킬/타격 단계의 방향·무게 프로필. 시전과 접촉을 구분 |
| 예상 명중 콜백의 직접 출력은 포즈/쉐이크/소리 중심 | Flow의 PersonalFeedback→AcceptFeedback→PlayOriginal, DrawEvent는 피해 숫자 | 접촉 지점에 별도 로컬 히트 스파크·충격 링·짧은 피격 강조 연결 |
| 스킬 소리가 시전 기준 고정 예약 | SkillSounds와 Schedule | 휘두름/대사는 시전, 접촉음은 명중, 폭발은 해당 폭발 이벤트에 맞춤 |

위 항목은 코드 확인이다. 사용자가 느낀 어색함의 기여도나 실제 화면·오디오 지연 수치는 이번에 측정하지 않았다. 이미 있는 스킬 이펙트가 전혀 없다는 뜻도 아니다.

## 구현 순서와 완료 기준

- [ ] **HF-01 사건 연결부터 정리.** encounter/행동/타격 단계/대상 키로 예측·확정 피드백을 연결한다. 현 Damage 이벤트에는 SourceId와 FeedbackKey가 있지만 스킬 ID·접촉 방향은 전용 필드가 없다. Zone의 Skill/SourceAction/HitIndex를 명중 시 캡처하는 방식을 검토한다. 이미 다음 모션으로 넘어간 현재 PlayerState만 보고 추측하지 않는다. 직렬화 변경 시 서버·클라이언트 묶음 버전도 함께 올린다.
- [ ] **HF-02 무기·소리 오류 수정.** 실제 공격자 무기로 소리 선택, 본인/파티 우선순위 분리, 다단히트 과도한 중첩 억제. 1P와 다른 무기를 쓰는 2~4P에서도 정확한 소리가 나야 한다.
- [ ] **HF-03 로컬 충돌 묶음.** 한 명중 키에서 접촉 FX·몸/무기 애니메이션 히트스톱·방향성 흔들림·접촉음 시작 시점을 함께 잡는다. 확정 이벤트가 나중에 와도 두 번 터지지 않아야 한다.
- [ ] **HF-04 세 기술부터 비교.** 평타/프렌지 연타, 블러드 소드 강타, 익스트림 오버킬 마무리. 하나의 범용 진동만 키우지 않고 리듬을 달리한다. 전후 동일 입력·동일 음량·동일 화면 크기로 녹화한다.
- [ ] **HF-05 전 스킬 확장.** 블러디 레이브 등 다단형과 각성 마무리 포함21종 검토. 다단 중간타는 짧게, 마지막 타격에 강세. 공중/달리기 공격도 접촉 위치와 무기 궤적 일치 확인.
- [ ] **HF-06 파티 화면 정리.** 타인 효과의 밝기·밀도·볼륨을 줄이고 본인 효과와 보스 경고를 우선 표시. 다른 방 효과가 들어오거나 타인 일반 타격이 내 히트스톱을 발생시키면 실패.

### 첫 비교용 값 — 확정 수치 아님

| 종류 | 로컬 애니메이션 히트스톱 초안 | 연출 초점 |
|---|---|---|
| 평타·프렌지 | 35~55ms | 베기 궤적과 접촉점, 콤보 마지막 타격 구분 |
| 블러드 소드 등 강타 | 70~95ms | 찌름의 접촉/폭발을 구분하고 각 시점에 강조 |
| 다단 중간타 | 0~20ms | 소리·스파크 리듬, 지속 정지 방지 |
| 오버킬·각성 마무리 | 100~130ms | 짧은 충격 강조 후 큰 잔광/저음·감쇠 |

연속 명중이 정지 시간을 무한 연장하지 않도록 누적 상한과 재발동 간격을 둔다. global Time.timeScale이나 전투 시뮬레이션을 멈추지 않는다. 보스 경고/충격파·점프 높이·HUD·네트워크는 계속 진행한다. 화면상의 보스 피격 강조가 실제 무력화나 공격 취소로 오해되지 않도록 일반 명중 플래시와 무력화 연출을 구분한다.

## 수동 합격 조건

- [ ] 소리를 끈 영상에서 접촉 위치와 강타/약타가 구분된다.
- [ ] 파티원 셋이 공격해도 내 평타와 마무리 소리를 식별할 수 있다.
- [ ] 준비 프레임에 충돌음이 먼저 나거나, 명중 후 한참 뒤 스파크가 생기지 않는다.
- [ ] 예측 명중이 빗나감으로 정정될 때 피해 숫자/사망/공통 연출을 확정처럼 보여주지 않는다. 이미 재생한 소리는 되돌릴 수 없다는 한계는 유지한다.
- [ ] 다단 공격 동안 화면이 계속 굳지 않고, 이펙트가 보스 예고·바닥 위험을 덮지 않는다.
- [ ] 60/120fps, 유저가 쓰는 해상도, 단독/4인 동시 각성, 지연 환경에서 확인한다.
- [ ] 전후 전투 확정 상태/피해/점프 회피 결과는 같다. 시각 개선으로 규칙이 바뀌지 않는다.
- [ ] 본인 수동 플레이 후 ‘공격이 닿는 순간과 끝나는 순간이 분명하다’는 평가를 받는다. 자동 테스트만으로 타격감 완료 처리하지 않는다.
