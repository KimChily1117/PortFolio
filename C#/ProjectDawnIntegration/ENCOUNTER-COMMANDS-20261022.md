# 바칼 첫 조우 · 프렌지 토글 · 커스텀 커맨드

이 문서는 v18 구현 기록이다. 현재 v19의 용 변신·폐허 전장·유리 농도 보완·피해 조정·점프 날개는 [후속 구현 문서](PHASE2-STOMP-20261022.md)를 따른다. 프렌지 토글과 커스텀 커맨드는 유지한다.

사용자가 2026-10-22 제공 녹화 기준 조우 적용을 승인했다. 메테오 표식은 앞서 확인한 큰 붉은 타원을 유지한다. AWS는 전원·리소스·배포 모두 변경하지 않는다.

## 첫 조우

영상 `04-07-42`의 약3초부터를 기준으로 14초 조우를 재구성했다. 왕좌 접근 → 손/와인잔 확대 → 잔 파손·파편·와인 → 얼굴 → 빠른 줌아웃 → 기립·상의 소멸 → 도약 → 전투 구도로 변경 → 착지 폭발·화면 흔들림 → 조작 복귀다.

원본 이미지14종244프레임과 왕좌 타일을 사용했다. 원본 픽셀과 영상상의 순서는 확인했으나 카메라 수치·프레임 지속 시간·도약/착지 본체 매핑은 이 데모의 재구성이다. 원본 ANI/넉백 규칙 복구로 표현하지 않는다. 착지는 화면/음향 연출이며 물리 넉백·피해를 새로 추가하지 않았다.

추가 요청한 유리잔의 용 얼굴은 원본 `glassc.img` 35프레임에 그려진 눈·비늘·이빨을 확인하여 연결했다. `glassb.img` 35프레임의 주변 파편도 함께 사용한다. 잔 파손 뒤 데모 5.08~6.43초(참고 영상 약8.2~9.4초 대응)에 표시하며 이후 얼굴 클로즈업으로 전환한다. 원본 합성 셰이더 복원이 아닌 straight alpha 근사다.

공유 `IntroEnabled`와 840틱으로 동기화한다. 착지 cue는708틱(11.8초). 조우 중 네트워크 틱은 계속 진행하지만 전투 제한시간, 이동, 점프, 공격, 버프 소모시간, 패턴·불바다는 진행하지 않는다. 조우 중 스킬 입력은 보관하지 않으며 종료 후 갑자기 발동하지 않는다. 최초 표식 일정도840틱 밀어서 전투 시작5초 뒤가 된다.

이 상태는 스냅샷과 롤백에 포함된다. 재접속자는 처음부터 다시 재생하는 대신 공유 시간의 현재 장면을 받는다. 클라이언트 예측은 카메라/본인 표시만 담당하며 방장 제안·서버 검증 구조를 유지한다.

## 프렌지

- 기존 전투 시작 자동ON 유지. 같은 스킬을 다시 쓰면OFF, 다시 쓰면ON.
- ON은 수동으로 끌 때까지 유지한다. 이전600초 자동 만료를 없앴다.
- OFF이면 보조 혈검과 이도류 평타를 해제하고 기본 평타 첫 동작으로 돌아간다.
- 양쪽 전환 간격은0.6초. 진행 중 공격은 기존 입력 버퍼/후딜 규칙을 따른다.
- OFF는 발동 이펙트·음성을 다시 재생하지 않는다. 상태/공격력 배율은 서버 공통 C#에서 검증한다.
- 폭주는 기존 시간제 버프이며 이번에 토글로 바꾸지 않았다.

## 커맨드

| 기능 | 기본값 |
|---|---|
| 폭주 | 앞, 앞, Space |
| 프렌지 ON/OFF | 아래, 아래, Space |
| 설정 | F6 또는 K스킬창의 커맨드 설정 |

앞/뒤는 첫 입력 당시 바라보는 방향이다. 방향키·Z·X·Space로2~8개 조합을 지정하고 마지막 키는Z/X/Space로 끝낸다. 키 사이0.45초, 전체1.4초. 같은 방향은 떼었다가 다시 누른다. 기존 앞앞 달리기/슬롯 단축키도 유지한다.

완성된 마지막 버튼은 일반 대시/공격/슬롯과 중복 실행하지 않는다. 설정은 이 PC의 PlayerPrefs에 저장하며 SQL/다른 PC와 동기화하지 않는다. 상세 구현과 인식기 검사는 [커맨드 문서](COMMAND-INPUT-20261022.md)에 있다.
