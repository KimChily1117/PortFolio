# 5분 시연과 면접 설명

[프로젝트 소개](README.md) · [기술 사례](TECHNICAL_CASE_STUDY.md)

## 30초 프로젝트 소개

> Cocos2d-x에서 4인 턴제 전투와 데이터 기반 스킬 연출을 연결한 프로젝트입니다. 에픽세븐 설치본의 애니메이션과 연출 데이터를 분석해 호환 계층을 구성했고, 전투 결과 계산과 화면 표시를 분리했습니다. 특히 Auto에서도 평타가 접근·타격·복귀까지 끝나도록 만들고, 스킵·일시정지·승리 전환에서 HP와 연출 상태가 어긋나지 않는지 검사했습니다. Windows 테스트와 Galaxy S8+ 실행으로 검증했습니다.

## 이력서에 넣을 짧은 설명

**Cocos2d-x 턴제 전투·스킬 연출 재구현**

- 전투 모델과 표시 이벤트를 분리해 일반 공격·S3의 HP 표시, 스킵, 승패 전환을 일관되게 처리.
- Spine 레거시 포즈 호환과 SEQANI/CFX 시간표 기반 연출을 연결하고, 평타·적 공격의 접근·타격·복귀 단계를 구현.
- CTest 7개, 변환기 회귀 검사, S3 의존 모델 21개 및 WebP 컷인 427개 검증; Galaxy S8+ 업데이트 설치와 기존 저장 보존 확인.

실제 역할·참여 기간·기여율은 본인이 확인할 수 있는 정보로 별도 작성합니다. 이 문서의 검증 기준일을 전체 개발 기간으로 사용하지 않습니다. 캐릭터·배경·사운드 제작이나 외부 변환 도구의 원저작을 본인의 기여로 기재하지 않습니다. REA와 Codex 등 사용한 분석·개발 도구도 설명할 수 있도록 준비합니다.

## 5분 발표 순서

| 시간 | 보여줄 자료 | 설명할 핵심 |
|---|---|---|
| 0:00–0:40 | 프로젝트 소개와 로비 화면 | 목표, 플랫폼, 현재 4명 S3 지원 범위 |
| 0:40–1:15 | 25초 실기기 영상 | 클라릿사 접근, 적의 대상 예고와 접근, 복귀까지 기다리는 Auto |
| 1:15–2:15 | 전투/연출 구조도 | 결과 계산과 displayedHp 분리, 이벤트 큐와 단일 타격 반영 |
| 2:15–3:15 | 일반 공격 또는 Spine 호환 사례 | 원인을 데이터에서 확인하고 책임을 분리한 과정 |
| 3:15–4:15 | 검증 표와 Android 결과 | 로직 검사→실제 렌더러→실기기, 저장 이전 실패의 처리 |
| 4:15–5:00 | 한계·후속 계획 | 4개 S3, 로컬 전투 규칙, 패키지 경량화와 지원 확장 |

기존 영상은 S3를 끈 상태의 일반 공격 검증본(v5), 25.02초·무음입니다. 최종 설치본(v6)은 같은 일반 행동 구현에 S3 대체 경로의 음향 정리와 검사 옵션을 추가한 빌드입니다. 녹화 영상의 프레임률을 게임 성능 측정치로 소개하지 않습니다.

## 직접 실행할 때의 시연 순서

1. 로비에서 모험 시작→스테이지→4인 편성→출전으로 이동합니다.
2. Auto OFF에서 기다려 HP와 행동 순서가 자동 진행하지 않는 모습을 보입니다.
3. S1과 적 대상을 선택해 접근/시전→타격→복귀를 보여 줍니다.
4. Auto를 켜 아군·적이 같은 행동 대기 규칙을 사용하는 모습을 보입니다.
5. 메뉴로 일시정지한 뒤 재개합니다. 이어 스킬 연출 ON에서 지원 영웅의 S3를 보여 줍니다.
6. 결과 화면과 로비 복귀로 마무리합니다. 실기기 상태에 따라 준비된 영상·화면 자료를 함께 사용합니다.

Windows에서는 정지·재개를 검증했습니다. Android v5에서는 4초 정지 화면 일치를 확인했고 해당 전투 재개는 후속 설치 때문에 검사하지 않았습니다. Android v6의 Home 후 앱 재개는 별도로 확인했습니다.

## 예상 질문과 답변 요점

### 왜 전투 결과를 먼저 계산하나요?

게임 규칙을 렌더링 시간에 종속시키지 않기 위해서입니다. 모델의 결과를 큐에 보관하고 화면 HP를 따로 유지하면, 스킵하거나 배속을 바꿔도 같은 결과를 표시할 수 있습니다. 대신 모델이 다음 행동자를 준비해도 실제 다음 행동 호출은 현재 연출 종료까지 막아야 합니다.

### FIRE가 없는 스킬은 어떻게 처리했나요?

원본에 없는 타격 이벤트를 복구된 값처럼 만들지 않았습니다. 해당 S3는 완료 시 아직 표시하지 않은 결과를 한 번 반영합니다. 일반 공격의 일부 미확인 시점은 클립 길이의 55%라는 로컬 규칙으로 분리해 기록했습니다.

### 원본 공격 애니메이션만 재생하면 안 되나요?

조사한 S1/S2 리그에는 전장을 가로지르는 루트 이동이 없었습니다. 클립은 몸과 무기를 움직이고, 접근과 복귀는 호스트가 제어해야 했습니다. 클라릿사 시퀀스의 점프→공격→복귀 구조를 근거로 행동 단계를 나눴습니다.

### Spine 버전 문자열을 바꾸면 호환되지 않나요?

기본값과 변환 상속의 의미가 달라서 충분하지 않았습니다. 생략 scale과 명시적 0을 구분하고, 2.1 계열 회전·스케일 상속과 반전을 별도로 처리했습니다. 실제 포즈·메시를 검사해 파일 파싱 성공과 렌더링 성공을 구분했습니다.

### 원작과 어디까지 같은가요?

원본 모델·시퀀스·레이아웃에서 확인한 자료를 사용했지만 전투 수치와 AI는 로컬 구현입니다. 복합 S3는 현재 4명이며, 카메라·파티클·음향의 일부 의미는 미확인입니다. 원본 소스나 서버를 복원했다고 설명하지 않습니다.

### 가장 실제적인 플랫폼 문제는 무엇이었나요?

Android 저장 백업의 하드 링크 발행 실패였습니다. 원본을 보존한 상태로 실패를 드러내고, Android 9에 맞는 renameat2 시스템 호출과 덮어쓰기 금지 옵션으로 바꿨습니다. 실제 업데이트 후 진행도와 1회 적립금 이전을 확인했습니다.

### 다음에 무엇을 개선하겠습니까?

첫째, 원본 근거가 확보된 공격 이벤트와 S3를 늘립니다. 둘째, 실기기에서 아직 확인하지 못한 라이브러리 개별 재생을 검사합니다. 셋째, 전체 자료를 담은 패키지를 실제 사용 의존성 중심으로 나눕니다. 적의 패턴·난이도 조정은 별도 전투 설계 과제로 진행할 수 있습니다.
